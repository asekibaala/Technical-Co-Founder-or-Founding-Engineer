# Interview Question Generator

A small web app that takes a job title and returns three thoughtful, role-specific
interview questions generated by an LLM.

Built as a 30-minute technical screen for a founding-engineer role.

**Live demo:** https://interview-q-ai.vercel.app/

---

## Stack & decisions

| Choice | Why |
|---|---|
| **Next.js 15 (App Router)** | One repo for UI + API. The API route hides the Gemini key server-side instead of leaking it in the browser bundle. |
| **Vercel** | Zero-config deploy from GitHub. Stays warm — reviewers clicking the link days later won't hit a cold start. |
| **Gemini 2.5 Flash** | Free tier with no credit card, fast, supports structured JSON output via `responseSchema`. Considered Groq (also free, very fast) and Claude Haiku (better reasoning, but no free tier without a card) — Gemini won on the cost/latency/zero-friction balance. |
| **Tailwind** | Fastest path to a clean, readable UI without writing CSS. |
| **TypeScript** | Catches shape errors at the API boundary for free. |

## The prompt

The system prompt asks the model to act as an experienced hiring manager and return
exactly three questions: one **behavioral**, one **role-specific**, and one
**situational**. Output is constrained to JSON via Gemini's `responseSchema`, so the
client gets a predictable `{ questions: string[] }` instead of free-form text that
would need fragile parsing.

See [`app/api/questions/route.ts`](app/api/questions/route.ts) for the full prompt.

## Run locally

```bash
# 1. Install
npm install

# 2. Get a free Gemini API key (no credit card required)
#    https://aistudio.google.com/apikey
#    - Sign in with a Google account
#    - Click "Create API key" → "Create API key in new project"
#    - Copy the key

# 3. Configure
cp .env.example .env.local
# then open .env.local and paste your key into GEMINI_API_KEY=

# 4. Run
npm run dev
# open http://localhost:3000
```

## Deploy to Vercel

1. Push this repo to GitHub.
2. Go to [vercel.com/new](https://vercel.com/new), import the repo (free Hobby tier).
3. Under **Environment Variables**, add `GEMINI_API_KEY` with your key.
4. Click **Deploy**. You get a live URL in ~60 seconds.
5. Future `git push` to `main` auto-redeploys.

## Project layout


## Security & privacy notes

- The Gemini API key lives in `process.env` and is only read inside the API route —
  it is never sent to the browser.
- The user's input is trimmed and length-capped (120 chars) before being sent to
  the model.
- No personal data is collected, logged, or persisted. Each request is stateless.

## What I'd improve with more time

- **Streaming** the response token-by-token for a snappier perceived latency.
- **Rate limiting** the API route (e.g. Upstash) since the key is server-side but
  the endpoint is open.
- **Question-type tabs** — let the user pick "behavioral only" or "more situational."
- **Tests** — a small Vitest suite around input validation and the response parser.
- **Telemetry** — log model latency and token usage to learn what to optimize.

## On using AI to build this

I used Claude Code to scaffold the project structure, draft the prompt iteratively,
and pair on the API route's input validation and error handling. The architectural
choices (Next.js + Vercel + Gemini, structured JSON output, server-side key) were
mine; the AI sped up the typing, not the thinking.
